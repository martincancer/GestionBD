Cursores
en SQL Server

Cómo procesar resultados fila por fila cuando una solución basada en conjuntos no alcanza, entendiendo el ciclo completo del cursor, sus costos y sus usos más razonables.

¿Qué son los cursores?

Un cursor es un objeto de SQL Server que permite recorrer el resultado de una consulta fila por fila, en lugar de trabajar con el conjunto completo de una sola vez.

SQL está pensado para trabajar por conjuntos. Un cursor rompe ese enfoque para resolver lógica procedural: recorrer, decidir, actualizar y seguir con la siguiente fila.
ROW

Fila por fila

Sirve cuando cada fila necesita un tratamiento particular y no alcanza con un único UPDATE o SELECT masivo.

LIFE

Ciclo completo

Todo cursor sigue la misma secuencia: declarar, abrir, obtener filas, procesar, cerrar y liberar.

SQL

Ejemplos prácticos

La clase incluye tres ejemplos reales: impresión, actualización de totales y acumulados.

SET

No es la primera opción

Cuando el problema se puede resolver con JOIN, subconsultas o sentencias set-based, eso suele ser mejor.

Qué permite hacer un cursor

  • 1
    Posicionarse sobre filas específicas del resultado.
  • 2
    Recuperar una fila o un bloque reducido de filas.
  • 3
    Aplicar lógica condicional sobre la fila actual.
  • 4
    Controlar el procesamiento en escenarios donde la secuencia importa.

¿En qué casos se pueden usar?

Los cursores no son “malos” por definición. Tienen sentido cuando realmente necesitás lógica iterativa y el enfoque por conjuntos no resuelve el problema con claridad.

Usos recomendados
  • Scripts de mantenimiento o administración.
  • Procesos complejos con decisiones por fila.
  • Migraciones o transformaciones secuenciales.
  • Escenarios donde la lógica iterativa es el foco del problema.
Evitar en
  • Operaciones transaccionales de alto volumen.
  • Consultas frecuentes en producción.
  • Escenarios que se resuelven con JOIN o subconsultas.
  • Procesos donde una sola sentencia puede hacer el trabajo.
!
La regla práctica es simple: si se puede resolver con una sentencia basada en conjuntos, preferila. El cursor queda como recurso cuando la lógica por fila es realmente necesaria.

esqueleto_cursor.sql 
-- 1. Declarar el cursor
DECLARE NombreCursor CURSOR FOR
SELECT Columna1, Columna2
FROM Tabla
WHERE Condicion;

-- 2. Variables de apoyo
DECLARE @Variable1 INT, @Variable2 VARCHAR(100);

-- 3. Abrir
OPEN NombreCursor;

-- 4. Obtener la primera fila
FETCH NEXT FROM NombreCursor INTO @Variable1, @Variable2;

-- 5. Procesar mientras haya filas
WHILE @@FETCH_STATUS = 0
BEGIN
    -- Lógica aquí

    FETCH NEXT FROM NombreCursor INTO @Variable1, @Variable2;
END;

-- 6. Cerrar y liberar
CLOSE NombreCursor;
DEALLOCATE NombreCursor;
Instrucción Función
DECLARE CURSOR Define qué consulta va a recorrer el cursor.
OPEN Inicializa el cursor y deja listo el conjunto de resultados.
FETCH NEXT Trae la fila actual a variables escalares.
@@FETCH_STATUS Indica si el último FETCH fue exitoso.
CLOSE / DEALLOCATE Cierra el cursor y libera los recursos asociados.

1. Recorrer empleados e imprimir cada fila

Este ejemplo usa el cursor como herramienta de lectura secuencial: toma cada empleado y lo imprime con PRINT CONCAT.

cursor_empleados.sql 
DECLARE DemoCursor CURSOR FOR
SELECT Legajo, Apellido, Nombre, Sueldo FROM Empleados

DECLARE @legajo INT, @apellido VARCHAR(50), @nombre VARCHAR(50), @sueldo NUMERIC(18,2)

OPEN DemoCursor;
FETCH NEXT FROM DemoCursor INTO @legajo, @apellido, @nombre, @sueldo;

WHILE @@FETCH_STATUS = 0
BEGIN
    PRINT CONCAT(@legajo, '- ', @apellido, ', ', @nombre, ' - ', @sueldo)
    FETCH NEXT FROM DemoCursor INTO @legajo, @apellido, @nombre, @sueldo
END;

CLOSE DemoCursor;
DEALLOCATE DemoCursor;

2. Actualizar el total de cada venta

Acá el cursor recorre una consulta agrupada y usa cada fila calculada para impactar otra tabla con UPDATE.

cursor_totales.sql 
DECLARE DemoCursor CURSOR FOR
SELECT VentaID, SUM(Cantidad * Precio)
FROM VentasProductos
GROUP BY VentaID

DECLARE @ventaid INT, @total NUMERIC(18,2);

OPEN DemoCursor;
FETCH NEXT FROM DemoCursor INTO @ventaid, @total;

WHILE @@FETCH_STATUS = 0
BEGIN
    UPDATE Ventas SET Total = @total WHERE VentaID = @ventaid
    FETCH NEXT FROM DemoCursor INTO @ventaid, @total;
END;

CLOSE DemoCursor;
DEALLOCATE DemoCursor;

3. Calcular un acumulado cronológico

Este caso muestra un uso típico donde la secuencia importa: recorrer ventas por fecha e ir acumulando el total fila por fila.

cursor_acumulado.sql 
DECLARE DemoCursor CURSOR FOR
SELECT VentaID, Fecha, Total
FROM Ventas
WHERE Fecha >= '2023-01-01' AND Fecha < '2023-12-31'
ORDER BY Fecha

DECLARE @ventaid INT, @fecha DATE, @total NUMERIC(18,2), @acumulado NUMERIC(18,2) = 0;

OPEN DemoCursor;
FETCH NEXT FROM DemoCursor INTO @ventaid, @fecha, @total;

WHILE @@FETCH_STATUS = 0
BEGIN
    SET @acumulado = @acumulado + @total
    SELECT @ventaid AS VentaID, @fecha AS Fecha, @total AS Total, @acumulado AS Acumulado
    FETCH NEXT FROM DemoCursor INTO @ventaid, @fecha, @total
END;

CLOSE DemoCursor;
DEALLOCATE DemoCursor;

Ventajas y desventajas

El cursor puede resolver problemas reales, pero tiene un costo. Conviene entender qué gana y qué sacrifica frente a una solución set-based.

Ventajas
  • Facilita la lógica compleja fila por fila.
  • Permite decisiones condicionales durante el recorrido.
  • Es útil para scripts administrativos o procesos secuenciales.
Desventajas
  • Consume más recursos que una solución por conjuntos.
  • Puede ser mucho más lento en grandes volúmenes.
  • Complejiza el mantenimiento si se usa donde no hace falta.
i
Una buena práctica docente es mostrar primero la solución basada en conjuntos y dejar el cursor como alternativa cuando la lógica iterativa sea realmente el foco del problema.
