Ejercicio 1: costo de envio

Consigna

Redactar una consulta que retorne, para todas las ventas realizadas en el año 2023:

El peso total de los productos vendidos en cada venta (resultado de Cantidad * Peso del producto, sumado por venta), el total de la venta, la razón social del cliente y clasificar agregando una nueva columna, llamada CostoDeEnvio, según lo siguiente:

  • Hasta 10 kg : 0
  • Más de 10 kg hasta 50 kg : 1.000
  • Más de 50 kg hasta 100 kg : 5.000
  • Más de 100 kg hasta 200 kg : 10.000
  • Más de 200 kg : 15.000
Datos necesarios
  • 1
    Ventas aporta fecha, total y cliente.
  • 2
    Clientes aporta la razon social.
  • 3
    VentasProductos y Productos permiten calcular el peso.
Regla de negocio

El peso total se calcula como SUM(vp.Cantidad * p.Peso). Luego se clasifica con CASE para asignar el costo de envio segun el rango de kilogramos.

ejercicio_01_costo_envio.sql 
SELECT
    v.VentaID,
    v.Total,
    c.RazonSocial,
    SUM(vp.Cantidad * p.Peso) AS PesoTotal,
    CASE
        WHEN SUM(vp.Cantidad * p.Peso) <= 10 THEN 0
        WHEN SUM(vp.Cantidad * p.Peso) > 10 AND SUM(vp.Cantidad * p.Peso) <= 50 THEN 1000
        WHEN SUM(vp.Cantidad * p.Peso) > 50 AND SUM(vp.Cantidad * p.Peso) <= 100 THEN 5000
        WHEN SUM(vp.Cantidad * p.Peso) > 100 AND SUM(vp.Cantidad * p.Peso) <= 200 THEN 10000
        ELSE 15000
    END AS CostoDeEnvio
FROM VentasProductos vp
INNER JOIN Ventas v ON vp.VentaID = v.VentaID
INNER JOIN Clientes c ON v.ClienteID = c.ClienteID
INNER JOIN Productos p ON vp.ProductoID = p.ProductoID
WHERE v.Fecha BETWEEN '20230101' AND '20231231'
GROUP BY
    v.VentaID,
    v.Total,
    c.RazonSocial
GO
i
Como se usa SUM, las columnas no agregadas del SELECT deben aparecer en el GROUP BY.

Ejercicios 2 y 3: subconsultas

Estos dos puntos trabajan subconsultas con objetivos distintos: una compara contra un valor promedio global y la otra cuenta ventas por cada empleado del listado externo.

2. Productos nacionales con precio mayor al promedio importado

Consigna

Redactar una consulta que devuelva el listado de productos nacionales cuyo precio sea mayor al precio promedio de todos los productos importados.

La consulta debe mostrar los siguientes campos:

  • Código del producto (Codigo),
  • Nombre del producto (Nombre),
  • Nombre de la marca (Marca),
  • Precio del producto (Precio)

La subconsulta devuelve un unico valor: el precio promedio de todos los productos importados. La consulta principal filtra los productos nacionales que superan ese promedio.

ejercicio_02_promedio_importados.sql 
SELECT
    p.Codigo,
    p.Nombre,
    m.Marca,
    p.Precio
FROM Productos p
INNER JOIN Marcas m ON p.MarcaID = m.MarcaID
WHERE p.Origen = 'N'
  AND p.Precio > (
      SELECT AVG(Precio)
      FROM Productos
      WHERE Origen = 'I'
  )
GO

3. Cantidad de ventas por vendedor

Consigna

Redactar una consulta que devuelva un listado de todos los empleados que ocupan el puesto de vendedor (PuestoID = 3), junto con la cantidad de ventas que realizaron. Utilizar una subconsulta correlacionada para contar las ventas de cada empleado vendedor.

Se deben mostrar los siguientes campos:

  • Apellido del empleado (Apellido)
  • Nombre del empleado (Nombre)
  • Cantidad total de ventas realizadas (Cantidad)

La subconsulta es correlacionada porque depende del empleado actual de la consulta externa mediante v.EmpleadoID = e.EmpleadoID.

ejercicio_03_ventas_por_vendedor.sql 
SELECT
    e.Apellido,
    e.Nombre,
    (
        SELECT COUNT(*)
        FROM Ventas v
        WHERE v.EmpleadoID = e.EmpleadoID
    ) AS Cantidad
FROM Empleados e
WHERE e.PuestoID = 3
GO
+
La diferencia central: en el ejercicio 2 la subconsulta puede resolverse una vez; en el ejercicio 3 se evalua vinculada a cada empleado de la consulta externa.

Ejercicio 4: trigger para recuperar stock

Consigna

Crear un trigger sobre la tabla VentasProductos para la acción de eliminación que realice lo siguiente: si se borra un registro de la tabla VentasProductos, se debe actualizar el stock del producto correspondiente, sumando el valor de la columna cantidad del registro eliminado al stock del producto.

En un trigger de eliminacion, la tabla virtual deleted contiene las filas que fueron borradas. Por eso se puede sumar d.Cantidad al stock del producto correspondiente.
DELETE en VentasProductos
->
deleted guarda la fila eliminada
->
Productos recupera stock
ejercicio_04_trigger_stock.sql 
CREATE TRIGGER TR_DelVentasProducto_Stock
ON VentasProductos
AFTER DELETE
AS
BEGIN
    UPDATE p
    SET p.Stock = p.Stock + d.Cantidad
    FROM Productos p
    INNER JOIN deleted d ON p.ProductoID = d.ProductoID
END
GO
!
El trigger esta escrito para trabajar tambien si se eliminan varias filas en una misma operacion, porque usa un UPDATE con JOIN contra deleted.

Ejercicio 5: validar legajo duplicado

Consigna

Crear un trigger para la acción de inserción en la tabla Empleados que verifique si existe el número de legajo indicado no permita la carga del empleado.

La solucion muestra dos enfoques posibles: AFTER INSERT y INSTEAD OF INSERT.

AFTER INSERT

La insercion ocurre primero. Si el trigger detecta duplicado, informa el error y ejecuta ROLLBACK TRANSACTION.

INSTEAD OF INSERT

El trigger reemplaza la insercion original. Si no hay duplicado, inserta explicitamente las filas recibidas en inserted.

Opcion con AFTER

ejercicio_05_legajo_after.sql 
CREATE TRIGGER TR_InsEmpleados_Legajo
ON Empleados
AFTER INSERT
AS
BEGIN
    IF (
        SELECT COUNT(*)
        FROM Empleados e
        INNER JOIN inserted i ON e.Legajo = i.Legajo
    ) > 1
    BEGIN
        RAISERROR('El numero de legajo ya existe. No se puede insertar el empleado.', 16, 1)
        ROLLBACK TRANSACTION
    END
END
GO

Opcion con INSTEAD OF

ejercicio_05_legajo_instead_of.sql 
CREATE TRIGGER TR_InsEmpleados_Legajo
ON Empleados
INSTEAD OF INSERT
AS
BEGIN
    IF (
        SELECT COUNT(*)
        FROM Empleados e
        INNER JOIN inserted i ON e.Legajo = i.Legajo
    ) > 0
    BEGIN
        RAISERROR('El numero de legajo ya existe. No se puede insertar el empleado.', 16, 1)
    END
    ELSE
    BEGIN
        INSERT INTO Empleados
        SELECT
            Legajo,
            Apellido,
            Nombre,
            NroDoc,
            Cuil,
            Sexo,
            Domicilio,
            CiudadID,
            TelPers,
            EmailLab,
            EmailPers,
            FechaNac,
            FechaIngreso,
            Comision,
            Sueldo,
            JefeID,
            PuestoID,
            HorasJornada,
            FechaBaja,
            EsActivo
        FROM inserted
    END
END
GO
i
En una base real conviene reforzar esta regla con una restriccion UNIQUE sobre Legajo, para que la integridad no dependa solo del trigger.
